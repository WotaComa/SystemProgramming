### Ситуация для обсуждения

Представьте, что в программе магазина из первого занятия уже есть рабочий модуль печати чеков. Он давно используется, протестирован и менять его рискованно. Теперь требуется добавить экспорт отчётов в другой формат.

Старый компонент принимает отдельные строки, а новая часть программы работает с объектом `Report`.

```cs
// Старый модуль
public class LegacyReportPrinter
{
    public string Print(string title, string body, string footer)
    {
        return $"=== {title} ===\n{body}\n{footer}";
    }
}
```

Новая часть приложения хочет вызывать метод так:

```cs
string result = exporter.Export(report);
```

Вопрос группе: как соединить эти две части, если старый класс менять нельзя?

Подводим студентов к идее: между старым и новым компонентами нужен посредник, который преобразует вызов и данные.

В этом занятии мы не учимся заново читать и исправлять старый код. Мы учимся строить совместимый слой поверх уже существующего кода.

## Теория

### Контракт взаимодействия

Контракт определяет, как один компонент взаимодействует с другим: какие данные передаёт, какой результат получает и какие ошибки могут возникнуть.

Для новой системы вводим модель отчёта:

```cs
public record Report(
    string Title,
    string Body,
    DateTime CreatedAt
);
```

И общий контракт экспорта:

```cs
public interface IReportExporter
{
    string Export(Report report);
}
```

Теперь клиенту не нужно знать, как именно формируется отчёт. Ему достаточно знать, что объект реализует `IReportExporter`.

Обсудите со студентами:

- Почему приложению удобнее передавать один объект, а не три отдельных строки?
- Что должен гарантировать метод `Export`?
- Должен ли клиент знать, печатает экспортёр отчёт, формирует Markdown или сохраняет его в файл?

Главный вывод: клиент зависит от контракта, а детали реализации остаются внутри конкретного компонента.

### Паттерн Adapter

Adapter (адаптер) — структурный паттерн, позволяющий использовать существующий компонент через другой интерфейс.

В нашей задаче адаптер:

1. Реализует `IReportExporter`.
2. Получает `Report`.
3. Преобразует его свойства в параметры старого метода.
4. Вызывает `LegacyReportPrinter.Print`.
5. Возвращает результат клиенту.

Важно различать две вещи:

- Адаптация интерфейса — преобразование способа вызова и входных данных.
- Переписывание старого компонента — изменение его внутреннего устройства.

В этом уроке старый класс менять нельзя. Все преобразования выполняются в адаптере.

### Композиция и расширяемость

Адаптер хранит экземпляр старого компонента:

```cs
private readonly LegacyReportPrinter _printer;
```

Это пример композиции: адаптер использует другой объект, но не наследуется от него.

Затем создаём ещё один класс, который тоже реализует `IReportExporter`, но формирует Markdown.

В результате основной код не меняется:

```cs
IReportExporter exporter = /* выбранная реализация */;

Console.WriteLine(exporter.Export(report));
```

Меняется только объект, который назначен переменной `exporter`.

Здесь применяется полиморфизм, но в контексте этого урока основной акцент не на повторном изучении ООП, а на практической пользе общего контракта при интеграции модулей.

## Demo

Прослеживаем путь данных от клиента до старого компонента.

```cs
using System;

public record Report(
    string Title,
    string Body,
    DateTime CreatedAt
);

public interface IReportExporter
{
    string Export(Report report);
}

// Старый компонент: его код не меняем.
public class LegacyReportPrinter
{
    public string Print(string title, string body, string footer)
    {
        return $"=== {title} ===\n{body}\n{footer}";
    }
}

// Новый адаптер.
public class LegacyReportAdapter : IReportExporter
{
    private readonly LegacyReportPrinter _printer;

    public LegacyReportAdapter(LegacyReportPrinter printer)
    {
        ArgumentNullException.ThrowIfNull(printer);
        _printer = printer;
    }

    public string Export(Report report)
    {
        ArgumentNullException.ThrowIfNull(report);

        string footer =
            $"Создан: {report.CreatedAt:yyyy-MM-dd HH:mm}";

        return _printer.Print(
            report.Title,
            report.Body,
            footer
        );
    }
}

/**
* 1. Где происходит преобразование данных?
* 2. Почему `LegacyReportPrinter` не реализует новый интерфейс?
* 3. Как проверить, что старый класс не пришлось изменять?
* 4. Что нужно поменять, если вместо старого принтера потребуется Markdown-экспортёр?*
*/
public class Program
{
    public static void Main()
    {
        Report report = new(
            "Отчёт по оборудованию",
            "В наличии: 12 ноутбуков; 8 мониторов.",
            new DateTime(2026, 10, 28, 9, 0, 0)
        );

        IReportExporter exporter =
            new LegacyReportAdapter(new LegacyReportPrinter());

        Console.WriteLine(exporter.Export(report));
    }
}
```

Ожидаемый вывод:

```
=== Отчёт по оборудованию ===
В наличии: 12 ноутбуков; 8 мониторов.
Создан: 2026-10-28 09:00
```
